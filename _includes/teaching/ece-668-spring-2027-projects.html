Project 1 · Network Behavior and Performance

Is the shortest path always the fastest? Investigate how traffic and link conditions move the bottleneck.

  • Starter: a two-path queue simulator with routing baselines, packet traces, and plots.
  • Task: implement an adaptive path-selection policy and compare it under normal load, bursts, and degraded links.
  • Evidence: throughput, tail delay, and packet loss; explain when the policy helps or fails.

Project 2 · Learning from Network Data

Can a small model predict network demand when traffic patterns change?

  • Starter: a synthetic traffic generator, independent data splits, simple predictors, and a trainable linear model.
  • Task: choose features and history windows, train a predictor, and compare it with the baselines.
  • Evidence: prediction errors on unseen traffic and failure cases, with checks for data leakage.

Project 3 · Programmable Networks and Intelligent Decisions

How should limited resources be shared between delay-sensitive and high-throughput services?

  • Starter: a two-class allocation simulator, rule-based policies, Q-learning, and evaluation on held-out episodes.
  • Task: build an optimization-based or learned policy and test its behavior across traffic conditions and repeated runs.
  • Evidence: throughput, delay, fairness, and resource-constraint checks.

Project 4 · Open-Ended Network Intelligence Project

Choose a networking problem and test what a model, controller, or agent contributes.

  • Starter: the default track provides a diagnostic-agent sandbox, expert demonstrations, decision-tree policy training, and tool-trajectory evaluation.
  • Task: define a testable question, build or train a method, and compare it with a baseline on held-out scenarios.
  • Evidence: network or task performance, resource costs, and failure cases; agent projects also examine tool-use errors and action outcomes.

Alternative topics include routing, scheduling, edge offloading, AI-RAN, ISAC, and network automation. Explore ideas during Weeks 8–9. Confirm data, interfaces, and compute needs in the proposal; GPU resources and live testbed access depend on availability.

What to Submit

Each submission includes runnable code, experiment configurations, key figures, a concise analysis, and a short demonstration or explanation.
